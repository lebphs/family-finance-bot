# Family Finance Mini App — план реализации

Связанный документ: [требования](./MINI_APP_REQUIREMENTS.md).

План разбит на последовательные этапы. Каждый этап должен завершаться
проверяемым результатом, автоматическими тестами для добавленной бизнес-логики
и отдельным логическим коммитом. Переход к следующему этапу выполняется после
проверки критериев готовности текущего.

## Общие правила реализации

- Не подключаться к реальному Telegram или Google Sheets в автоматических
  тестах; внешние границы заменять mock/fake-реализациями.
- Все обработчики Telegram и HTTP API оставлять асинхронными.
- Блокирующие вызовы `gspread` выполнять через `asyncio.to_thread` или
  изолированный асинхронный сервис.
- Не менять существующие столбцы A–D листа `Transactions`.
- Не выводить в логи `.env`, токен бота, Google credentials и Telegram
  `initData` целиком.
- Не давать frontend прямого доступа к Google Sheets или секретам.
- Проверять авторизацию и права на backend для каждой защищённой операции.
- Сохранять русский язык пользовательского интерфейса.

## Этап 0. Подготовка проекта и безопасность

### Задачи

- Проверить текущее состояние репозитория и не затрагивать пользовательские
  изменения (`Procfile`, `google-credentials.json` и другие несвязанные файлы).
- Выбрать единую поддерживаемую версию Python для Docker и окружения запуска.
- Добавить `.dockerignore`, исключив `.env`, Google credentials, кеши Python,
  тестовые артефакты и локальные файлы frontend.
- Проверить `.gitignore` и исключение секретов из новых коммитов.
- Подготовить единый модуль конфигурации с обязательной валидацией переменных
  окружения.
- Создать структуру тестов и базовые проверки запуска.
- Описать безопасную миграцию Google Sheets и резервное копирование перед ней.
- За пределами кода: заменить токены и credentials, которые ранее могли попасть
  в историю Git.

### Критерии готовности

- Версия Python одинакова в конфигурациях проекта.
- Секреты не попадают в Docker build context и новые коммиты.
- Тестовая команда запускается и не обращается к внешним сервисам.
- Подготовлен план миграции таблицы с возможностью проверки до изменения данных.

## Этап 1. Backend-каркас

### Задачи

- Добавить приложение FastAPI.
- Разделить HTTP API, Telegram-обработчики, бизнес-логику и доступ к данным.
- Настроить совместный запуск FastAPI и aiogram без блокировки event loop.
- Добавить endpoint состояния приложения (`healthcheck`).
- Добавить единый формат ошибок API.
- Настроить журналирование без чувствительных данных.
- Ограничить CORS локальным frontend в разработке и адресом Mini App в рабочем
  окружении.
- Обновить Docker-конфигурацию для запуска backend.

### Предварительная структура API

```text
GET    /api/me
GET    /api/categories
GET    /api/transactions
POST   /api/transactions
PATCH  /api/transactions/{transaction_id}
DELETE /api/transactions/{transaction_id}
GET    /api/statistics
GET    /api/reminders
PUT    /api/reminders
GET    /api/admin/users
POST   /api/admin/users
PATCH  /api/admin/users/{telegram_user_id}
```

### Критерии готовности

- FastAPI и бот запускаются в согласованной конфигурации.
- Healthcheck отвечает без подключения к Telegram или Google Sheets.
- Ошибки API не раскрывают внутренние исключения и секреты.
- Есть тест запуска приложения.

## Этап 2. Telegram-авторизация и пользователи

### Задачи

- Реализовать серверную проверку подписи Telegram Mini App `initData`.
- Проверять `auth_date` и отклонять просроченные данные.
- Получать Telegram ID только из проверенных данных.
- Добавить модель текущего пользователя и роли `admin`/`member`.
- Добавить работу с листом `Users`.
- Запрещать доступ отсутствующим и неактивным пользователям.
- Реализовать административные операции для управления участниками.
- Добавить локальную dev-авторизацию, которая физически недоступна в production.

### Тесты

- корректная подпись;
- неверная подпись;
- отсутствующая подпись;
- просроченный `auth_date`;
- разрешённый, неизвестный и отключённый пользователь;
- разграничение ролей;
- невозможность включить dev-авторизацию в production.

### Критерии готовности

- Финансовые endpoints недоступны без валидного `initData`.
- Пользователь вне allowlist не получает финансовые данные.
- Роль и активность определяются только на backend.

## Этап 3. Слой Google Sheets и миграция данных

### Задачи

- Создать интерфейсы repositories для пользователей, категорий и транзакций.
- Изолировать `gspread` внутри реализации repositories.
- Убрать сетевые обращения при импорте Python-модулей.
- Выполнять блокирующие операции вне event loop.
- Добавить обработку временных ошибок и понятные прикладные исключения.
- Создать или проверить лист `Users`.
- Расширить новые строки `Transactions` столбцами E–I:
  - Telegram User ID;
  - имя автора;
  - постоянный `transaction_id`;
  - `created_at`;
  - `updated_at`.
- Сохранить текущие столбцы A–D и совместимость с существующими формулами.
- Поддержать старые строки без автора и ID.
- Назначить постоянные ID существующим строкам безопасной миграцией.
- Адаптировать месячную ротацию к расширенной структуре.
- Читать текущий лист и архивы `Transactions MM.YYYY`.
- Не использовать номер строки как постоянный идентификатор.

### Тесты

- чтение категорий и подкатегорий;
- создание транзакции с автором и ID;
- поиск, изменение и удаление по ID;
- старые строки без автора;
- чтение нескольких месячных листов;
- идемпотентная месячная ротация;
- повторный запуск миграции без дублирования данных.

### Критерии готовности

- Существующие данные и формулы в A–D сохранены.
- Каждая новая транзакция имеет автора и уникальный ID.
- Ошибка Google API не блокирует event loop и корректно сообщается API.
- Все операции покрыты тестами без реальной таблицы.

## Этап 4. Основа frontend и локальное тестирование

### Задачи

- Создать frontend на React, TypeScript и Vite.
- Подключить официальный Telegram Web App SDK.
- Передавать `initData` backend с каждым защищённым запросом.
- Создать типизированный API-клиент.
- Добавить нижнюю навигацию:
  - Главная;
  - Транзакции;
  - Статистика;
  - Настройки.
- Поддержать тему и безопасные области Telegram.
- Добавить экраны загрузки, пустого результата, ошибки и отсутствия доступа.
- Настроить локальный режим разработки.
- Подготовить запуск через временный HTTPS-туннель для проверки в Telegram.

### Способы проверки до публикации

1. Обычный браузер:
   - frontend работает на локальном адресе Vite;
   - backend работает на локальном адресе FastAPI;
   - используется только защищённая dev-авторизация.
2. Настоящий Telegram:
   - локальный сервер публикуется через Cloudflare Tunnel или ngrok;
   - временный HTTPS URL указывается в BotFather;
   - используются реальные и проверяемые Telegram `initData`;
   - компьютер и локальные процессы должны оставаться запущенными.

### Критерии готовности

- Интерфейс открывается в браузере без Telegram.
- Интерфейс открывается внутри Telegram через временный HTTPS-туннель.
- Светлая и тёмная темы корректно отображаются.
- Неавторизованный пользователь видит только экран отказа в доступе.

## Этап 5. Главная страница и первая MVP-версия

### Задачи

- Реализовать форму добавления расхода.
- Загружать категории и подкатегории из `Preferences!B4:C43`.
- Проверять сумму, категорию и дату на frontend и backend.
- Определять автора только на backend.
- Защитить форму от повторной отправки.
- После сохранения обновлять сводку и список последних операций.
- Показать сумму текущего месяца.
- Показать изменение относительно предыдущего месяца.
- Добавить диаграмму расходов по категориям.
- Показать последние транзакции.

### Тесты

- корректная и некорректная сумма;
- неизвестная категория;
- дата вне допустимого формата;
- повторная отправка;
- автор берётся из авторизации, а не из тела запроса;
- успешное и неуспешное сохранение.

### Критерии готовности

- Разрешённый пользователь добавляет расход с телефона за один короткий
  сценарий.
- Новая операция появляется в Google Sheets с ID и автором.
- Сводка обновляется без перезапуска приложения.

После этого этапа получается первая версия, пригодная для ежедневного внесения
расходов.

## Этап 6. Управление транзакциями

### Задачи

- Добавить список от новых операций к старым.
- Реализовать постраничную загрузку.
- Добавить фильтры по периоду, категории и участнику.
- Добавить поиск по описанию.
- Показать автора каждой операции.
- Добавить просмотр и редактирование операции.
- Добавить удаление с явным подтверждением.
- Проверять права на изменение и удаление на backend.
- Разрешить `member` менять только свои операции.
- Разрешить `admin` менять любые операции, включая старые без автора.
- Обрабатывать ситуацию, когда операция уже была изменена или удалена.

### Критерии готовности

- Фильтры и поиск работают для текущего и архивных месяцев.
- Изменение выполняется по постоянному ID.
- Участник не может изменить или удалить чужую транзакцию прямым API-запросом.
- После операции интерфейс и Google Sheets показывают одинаковые данные.

### Задачи

- Добавить периоды: текущий месяц, 2, 3, 6 и 12 месяцев.
- Добавить произвольный диапазон месяцев.
- Добавить сравнение двух выбранных месяцев.
- Рассчитать расходы по категориям.
- Рассчитать динамику общей суммы по месяцам.
- Показать абсолютную и процентную разницу.
- Добавить фильтр «Вся семья / участник».
- Для каждого участника рассчитать:
  - общую сумму;
  - долю семейных расходов;
  - количество операций;
  - среднюю сумму;
  - категории;
  - динамику по месяцам.
- Реализовать сравнение участников.
- Строить диаграммы во frontend по данным API.
- Явно обрабатывать старые операции без автора.

### Критерии готовности

- Итоги совпадают с контрольными примерами из тестовых данных.
- Статистика учитывает текущий и архивные листы.
- Деление на ноль, пустые месяцы и неизвестный автор обрабатываются корректно.
- Можно переключаться между всей семьёй и конкретным участником.

## Этап 8. Напоминания, публикация и финальная проверка

### Напоминания

- Перенести настройки из памяти процесса в лист `Users`.
- Поддержать включение и отключение напоминаний.
- Поддержать время, дни недели и часовой пояс пользователя.
- Значения по умолчанию: ежедневно, 22:00, `Europe/Minsk`.
- Сохранить `chat_id` после разрешённого взаимодействия пользователя с ботом.
- Не отправлять одно напоминание повторно в рамках запланированного периода.
- Корректно восстанавливать расписание после перезапуска.
- Не удалять подписку из-за единичной временной ошибки Telegram.

### Публикация

- Собрать frontend и настроить его выдачу приложением или отдельным сервисом.
- Подготовить production Docker-образ без секретов.
- Передавать credentials через защищённые настройки хостинга.
- Развернуть приложение по HTTPS-адресу, предоставленному платформой.
- Настроить Main Mini App или кнопку меню в BotFather.
- Ограничить production CORS постоянным адресом приложения.
- Настроить резервное копирование Google Sheets и журналирование ошибок.

### Финальная проверка

- Android, iOS и Telegram Desktop;
- светлая и тёмная темы;
- администратор, участник и неизвестный пользователь;
- добавление, редактирование и удаление;
- статистика за несколько месяцев;
- перезапуск приложения и восстановление напоминаний;
- недоступность dev-авторизации;
- отсутствие секретов в frontend, Docker-образе и логах.

### Критерии готовности

- Mini App доступно по постоянному HTTPS URL.
- Напоминания работают индивидуально и переживают перезапуск.
- Все критерии первой версии из документа требований выполнены.
