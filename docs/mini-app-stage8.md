# Этап 8 — напоминания и выпуск

Код этапа реализован. Постоянная HTTPS-публикация и проверки настоящих клиентов
Telegram ещё не выполнены: требуются проект хостинга, URL и устройства.

## Персональные напоминания

- `GET /api/reminders`, `PUT /api/reminders` требуют обычную авторизацию Telegram.
- PUT принимает только `reminder_enabled` (boolean), `reminder_time` (`HH:MM`),
  `reminder_days` (непустой массив уникальных целых 0–6, понедельник = 0),
  `timezone` (IANA). Значения по умолчанию: выключено, 22:00, ежедневно,
  `Europe/Minsk`. Новые участники включают уведомления по своему желанию.
- Ответ дополнительно содержит `chat_connected`; клиент не может задать chat ID,
  чужой ID или роль. Настройки пишутся в существующие столбцы листа `Users`.
- `/start` и `/register` подключают **личный** чат активного разрешённого
  пользователя. `/start` предлагает кнопку Mini App при заданном MINI_APP_URL.
- `/subscribe [HH:MM]` включает персональные уведомления и сохраняет chat ID;
  без аргумента время 22:00. Дни и часовой пояс не сбрасываются.
  `/unsubscribe` отключает уведомления. Неизвестные/отключённые пользователи
  и групповые чаты не подключаются.
- Каждые 30 секунд бот перечитывает Users: изменения вступают в силу без
  перезапуска. Отправка после заданного времени в соответствующий локальный
  день позволяет восстановиться после простоя в пределах этого дня. За прошлые
  дни уведомления не досылаются. При переводе часов вперёд отправка выполняется
  при первой проверке после заданного времени.
- Постоянный `STATE_DIR/reminders.sqlite3` содержит уникальную отметку
  `(telegram_user_id, локальная дата)`. Отметка записывается **до** запроса Telegram;
  повторные проверки, изменение времени и рестарт не дают дубля в этот день.
- Telegram не поддерживает idempotency key: при аварии после отметки или
  неопределённом результате отправки напоминание за этот день может быть
  пропущено. Его повторная отправка могла бы дать дубль. Настройки/подписка
  сохраняются; следующий запланированный день обрабатывается нормально.
- Один экземпляр приложения, один polling-процесс, один постоянный том.
  Нельзя удалять том при redeploy; несколько реплик с независимыми томами
  нарушают гарантию отсутствия дублей. Файл SQLite не является финансовой БД.

## Production

Dockerfile собирает React/TypeScript в отдельном Node-этапе. Финальный Python
образ получает только backend, бот и готовый `mini_app/frontend/dist`, запускается от
непривилегированного пользователя, содержит healthcheck `/health`.
Frontend исходники копируются явным списком; `.env.local` не попадает в сборку.
FastAPI выдаёт `/` и `/assets/*`, защищённый API остаётся `/api/*`.
Ни корень репозитория, ни state, ни credentials не выдаются как static files.

Настройки хостинга:

| Переменная | Значение |
| --- | --- |
| `APP_ENV` | `production` |
| `DEV_AUTH_ENABLED` | `false` |
| `MINI_APP_URL` | Постоянный HTTPS origin, например `https://project.platform.example` |
| `BOT_TOKEN` | Новый токен из защищённой настройки хостинга |
| `GOOGLE_SHEET_ID` | ID рабочей таблицы из защищённой настройки |
| `GOOGLE_APPLICATION_CREDENTIALS` | Путь к секретному JSON-файлу, например `/run/secrets/google.json` |
| `STATE_DIR` | Путь к постоянному приватному тому, например `/app/data` |
| `BACKUP_ENABLED` | `true` по умолчанию |
| `PORT` / `API_PORT` | Порт платформы; `PORT` имеет приоритет |

Не передавать секреты через build args или VITE-переменные. Credentials
монтируются read-only либо предоставляются secret file механизмом платформы.
Таблица должна быть предоставлена сервисному аккаунту. Перед публикацией
заменить ранее раскрытые секреты по [инструкции](secret-rotation.md).
Production CORS допускает только origin MINI_APP_URL; dev-заголовок не действует.

Порядок публикации после выбора платформы:

1. Собрать Dockerfile и создать один сервис с HTTPS, healthcheck `/health`,
   постоянным томом STATE_DIR и настройками выше. Остановить старый polling того
   же бота. Не запускать несколько uvicorn workers/реплик.
2. Проверить `/health`, `/`, assets, отказ API без initData, запрет dev auth и
   правильный CORS. Проверить образ на отсутствие секретных файлов.
3. В BotFather выбрать бота → Bot Settings → Configure Mini App / Main Mini App,
   указать постоянный HTTPS URL. Либо настроить Menu Button с тем же URL.
   Отправить `/start` боту от каждого участника и включить напоминания в настройках.
4. Выполнить ручные проверки ниже. До их завершения версия 1 не считается выпущенной.

## Резервное копирование и журналирование

Бот ежедневно при первом доступном цикле сохраняет все листы, включая Users,
Preferences, Main, текущие и архивные Transactions, в
`STATE_DIR/backups/sheets-YYYY-MM-DD.json`. Снимок содержит значения и формулы,
сохраняется атомарно с приватными правами; хранится 30 последних снимков.
При ошибке неполный снимок не становится завершённым, следующий цикл повторяет
попытку. Снимки не включены в Git/Docker и не доступны через HTTP.

Это резервная копия данных и формул, не полная копия оформления/графиков Sheets.
Для восстановления остановить всех писателей, создать отдельную таблицу,
восстановить листы с исходными именами и строками из `formulas` (проверяя
формулы и текстовые значения), сверить заголовки/ID и контрольные суммы расходов,
только затем переключить GOOGLE_SHEET_ID. Рабочую таблицу автоматически не
перезаписывать. Для независимого disaster recovery настроить средствами
хостинга ежедневную защищённую копию тома в отдельное хранилище; локальный том
не защищает от удаления сервиса/диска. Снимки содержат финансовые и персональные
данные, доступ ограничивается владельцем приложения.

Ошибки пишутся в stdout/stderr для сборщика логов хостинга. Сообщения API/бота/
фоновых задач не печатают внешние исключения. Фильтр скрывает токены, initData,
Authorization и PEM private key; исключения сторонних библиотек не печатают
непроверенный traceback. На платформе нужны уведомления о недоступности healthcheck,
сбое polling и отсутствии свежей резервной копии.

## Финальная проверка

Автоматические проверки используют поддельные Telegram/Sheets, временные
SQLite/каталоги и перехват HTTP. Они покрывают API, права, расписания/таймзоны,
перезапуск, дубли, временную ошибку, сохранение Users, резервные копии,
выдачу frontend и CORS, форму и административные действия.

Ручная матрица (не отмечать завершённой без реальной проверки):

- [ ] Постоянный HTTPS адрес, BotFather Main Mini App/Menu Button.
- [ ] Android: светлая и тёмная темы, safe area, клавиатура, все разделы.
- [ ] iOS: те же проверки.
- [ ] Telegram Desktop: те же проверки.
- [ ] Admin/member/неизвестный/отключённый: корректный доступ.
- [ ] Создание, редактирование, подтверждённое удаление; свои/чужие/старые записи.
- [ ] Статистика текущего/архивных месяцев и участников.
- [ ] Персональные напоминания для разных времён/таймзон/дней; отключение.
- [ ] Рестарт/redeploy с сохранением тома, отсутствие дубля в этот день.
- [ ] Токены заменены, secret file read-only, секретов нет в образе/mini_app/frontend/логах.
- [x] Docker image собран и локально проверен; HTTP healthcheck доступен.

Повторить smoke-проверку из корня репозитория после сборки:

```bash
docker --context desktop-linux run --rm --network none \
  --mount type=bind,src="$PWD/scripts/verify_production_image.py",dst=/tmp/verify_production_image.py,readonly \
  -e PYTHONPATH=/app family-finance-mini-app:stage8 \
  python /tmp/verify_production_image.py
```

Для хостинга с архитектурой amd64 требуется отдельная сборка под linux/amd64;
локальная проверка arm64 не проверяет такую сборку.

кнопка меню бота и существующее персональное меню разрешённого участника

проверены с активным участником; ответы с финансовыми данными не выводились.
Неизвестный ID отклоняется. Локальная проверка не означает постоянную публикацию.

текстовые дни и идентификаторы, добавлен тест с настоящим numericise gspread.
Исправление не меняет схему или существующие строки таблицы.


После исправлений локального запуска все 128 backend-тестов прошли также в
