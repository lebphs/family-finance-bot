# Переход на SQLite

Основное хранилище — `STATE_DIR/finance.sqlite3`. Суммы сохраняются точными
десятичными строками. Расходы всех месяцев находятся в одной базе, пользователи,
права и настройки напоминаний — там же. Изменения интерфейса не требуются.
Google Sheets используется только как ежедневная выгрузка. Изменения расходов,
пользователей и настроек в старой таблице больше не влияют на приложение.
Категории импортируются один раз; последующие изменения справочника должны
вноситься в базу. Редактирование категорий через интерфейс пока не реализовано.

## Содержимое Google Sheets

- `DB Transactions`: дата, описание, категория, точная сумма, ID и имя автора,
  ID операции, время создания и изменения. Включает всю историю, без формул.
- `DB Categories`: категории и подкатегории.
- `DB Sync`: дата последней успешной выгрузки по времени Минска, источник и число расходов.

Старые `Main`, `Preferences`, `Users`, `Transactions` и месячные архивы не изменяются
и не удаляются. Их можно сохранить как архив после проверки переноса.
Рабочие листы экспорта целиком заменяются, включая удаление устаревших строк.
Не храните в листах `DB ...` ручные записи: следующая выгрузка их заменит.
Все значения выгружаются как текст: суммы без округления, ID без потери цифр,
описания с `=` не превращаются в формулы.

## Перенос

Не запускайте новую версию бота до импорта. Команда импорта не запускает polling.
Во время окончательного импорта остановите все приложения, которые пишут в Sheets.
Сначала сохраните резервную копию таблицы и предыдущий Docker-образ.
`STATE_DIR` должен указывать на тот же постоянный том для импорта и рабочего приложения.

Для локального запуска:

```sh
python -m mini_app.backend.database_migration
python -m mini_app.backend.database_migration --apply
python -m mini_app
```

Первая команда только читает таблицу и выводит количества записей.
Нужны корректный `Users`, хотя бы один активный администратор и категории.
Все расходы, включая архивы, должны иметь постоянные ID. Если IDs отсутствуют,
используйте существующую миграцию метаданных из `google-sheets-migration.md`
после резервного копирования. Импорт не меняет Google Sheets, не назначает авторов
старым расходам, сохраняет даты, ID и временные метки. Запись всех таблиц базы
происходит одной транзакцией; повторный импорт в заполненную базу запрещён.

Для VPS из `/opt/family-finance`, после передачи исходников:

```sh
docker image tag family-finance-mini-app:production family-finance-mini-app:before-sqlite
docker compose -f compose.production.yaml build bot
docker compose -f compose.production.yaml run --rm --no-deps bot python -m mini_app.backend.database_migration
docker compose -f compose.production.yaml stop bot
docker compose -f compose.production.yaml run --rm --no-deps bot python -m mini_app.backend.database_migration --apply
docker compose -f compose.production.yaml up -d --wait --wait-timeout 120 bot
```

Если импорт не прошёл, не запускайте новую версию с пустой базой: верните старый
образ и исходники. До первого запуска новая версия не меняет Sheets.
После появления новых расходов в SQLite откат на старую версию требует
отдельного переноса этих расходов: старая таблица больше не актуальна.

## Ежедневная работа

Планировщик проверяет выгрузку каждые 30 секунд. Первая успешная выгрузка в
календарный день считается ежедневной; точное время не фиксировано.
После простоя выполняется актуальная выгрузка в первый доступный цикл.
Успешная дата хранится в базе и переживает перезапуски. При сбое повтор через
5 минут. Обновление содержимого трёх листов выполняется одной атомарной операцией;
создание новых листов и увеличение их размера может происходить до неё.
Расходы, добавленные во время выгрузки, попадут в следующую ежедневную выгрузку.
Для работы используйте один процесс приложения с локальным постоянным диском.

При `BACKUP_ENABLED=true` перед выгрузкой сохраняется согласованная копия SQLite
через SQLite backup API. Хранятся последние 30 ежедневных файлов
`STATE_DIR/backups/finance-YYYY-MM-DD.sqlite3`, с приватными правами. Копии включают
пользователей и настройки, поэтому папка не должна быть публичной.
Если Google недоступен, локальная копия всё равно сохраняется. При ошибке
резервного копирования выгрузка откладывается до следующей попытки.

Для восстановления остановите приложение, сохраните текущие `finance.sqlite3`,
`finance.sqlite3-wal` и `finance.sqlite3-shm` в приватную папку. На место основного
файла поставьте нужную резервную копию; старые WAL/SHM не должны оставаться рядом
с восстановленным файлом. Проверьте владельца и права `0600`, затем запустите
приложение. Не удаляйте Docker-том (`down -v`). Выгрузка Sheets — удобный отчёт,
но не замена полной резервной копии базы.
