# Этап 7 — статистика

Реализован этап 7 из `mini-app-implementation-plan.md`. Изменения предыдущих
этапов сохранены; напоминания, публикация и остальные задачи этапа 8 не затронуты.

## API

`GET /api/statistics` требует ту же проверенную Telegram-авторизацию и активного
пользователя, что и остальные финансовые endpoints. Member и admin видят
семейную статистику. Неизвестный/отключённый пользователь не вызывает чтение
транзакций. API только читает книгу, не запускает миграцию и не меняет Sheets.

Параметры:

| Режим | Параметры | Значение |
| --- | --- | --- |
| `months` (по умолчанию) | `months=1`, `2`, `3`, `6`, `12` | N календарных месяцев, включая текущий по Europe/Minsk |
| `range` | `month_from`, `month_to` | Произвольный включительный диапазон `YYYY-MM` |
| `compare` | `compare_from`, `compare_to` | Два разных месяца, первый — база сравнения |

Во всех режимах: `author_id` — положительный Telegram ID либо
`unknown_author=true` — только расходы без автора. Без этих параметров — вся
семья. Некорректные месяцы, перевёрнутый диапазон, совпадающие месяцы сравнения,
противоречивые фильтры, параметры диапазона/сравнения в другом режиме и неизвестные параметры дают
`422`. Неактивные и неизвестные пользователи получают `403`, отсутствие или
некорректная авторизация — `401`, временная ошибка Sheets — `503` в общем формате.

Ответ:

- `months`: месяцы в хронологическом порядке; в режиме compare только два
  выбранных месяца, без промежуточных.
- `total`, `count`, `categories`, `monthly`: показатели выбранного автора или
  всей семьи. Категории отсортированы по сумме, месяцы включают нулевые значения.
- `family_total`: семейная сумма за те же месяцы независимо от фильтра автора.
- `comparison`: базовая и сравниваемая суммы, абсолютная разница
  `to_total - from_total`, процент относительно `from_total`; вне compare — null.
- `participants`: сравнение **всей семьи** за выбранные месяцы, независимо от
  фильтра автора: сумма, доля семейных расходов, число операций, средняя сумма,
  категории и динамика каждого автора.
- `available_participants`: только публичные ID и подписи авторов из всей книги,
  без ролей, статуса доступа, chat_id и настроек Users.

Участники берутся из книги транзакций, а не из административного списка Users;
авторы, чьи операции есть только вне периода, получают нулевые показатели.
Новая регистрация без расходов не создаёт строку статистики. Неизвестный
положительный ID в фильтре даёт пустой результат. При изменении имени выбирается
подпись из самой поздней по дате операции (при совпадении — по ID и подписи).

Старые операции с `author_id=null` объединены в группу «Автор не указан» и входят
в общий итог и знаменатель долей. Автором считается внёсший операцию участник,
а не обязательно человек, на которого потрачены деньги.

## Расчёты и интерфейс

Существующий repository за один вызов читает текущий `Transactions` и корректные
архивы `Transactions MM.YYYY`, выполняя gspread вне event loop. Период определяется
по дате операции, а не имени листа. Финансовые суммы рассчитываются через Decimal;
средние и проценты округляются до двух знаков, ROUND_HALF_EVEN. API отдаёт Decimal
строками. Нет серверных PNG и общего временного файла диаграммы.

Процентная разница и доля при нулевом знаменателе — `null`, интерфейс пишет
«не определён». Средняя сумма при отсутствии операций — 0. Первому месяцу
динамики разница не назначается; каждый последующий сравнивается с предыдущим
показанным месяцем. В режиме compare направление явно задаёт выбранный базовый
месяц, даже если он хронологически позже второго.

Экран «Статистика» поддерживает все периоды, выбор участника и старых расходов,
сравнение месяцев, диаграммы категорий, динамики и участников, раскрываемые
карточки с метриками, категориями и динамикой каждого участника. Диаграммы
строятся во frontend по числам API, с доступными текстовыми суммами BYN.
Цвета используют общие переменные темы Telegram. Есть загрузка, пустой результат,
ошибка с повтором и выход на экран отказа в доступе. Некорректные фильтры не
отправляются; устаревшие запросы отменяются и их поздние ответы игнорируются.
При входе в раздел данные читаются заново, в том числе после правок транзакций.

## Контрольный пример и проверки

За январь–март 2026 тестовые суммы: Иван — 60 BYN (3 операции, средняя 20,
доля 33,33%), Анна — 110 BYN (2 операции, средняя 55, доля 61,11%), без автора —
10 BYN (1 операция, доля 5,56%). Семья — 180 BYN. Месячные суммы — 60, 0, 120;
категории: транспорт 109,90, еда 70,10. От января к марту рост 60 BYN / 100%,
обратно −60 BYN / −50%. От нулевого февраля к марту +120 BYN, процент не определён.
Округлённые доли могут отличаться в сумме от 100% на сотую.

Команды (Python 3.11 и Node 22):

```sh
python -m unittest tests.test_statistics_stage7 -v
python -m unittest discover -s tests -v
cd mini_app/frontend
npm test
npm run build
npm run test:e2e
```

Все Google/Telegram границы подменены. Backend проверяет контрольные суммы,
фильтры, все пресеты, переход года, пустые месяцы, нулевые знаменатели, Decimal,
направление сравнения, чтение текущего и нескольких архивов без записи,
валидацию и отказ до чтения финансов. Frontend проверяет отображение,
параметры, переключение автора, ошибки и повтор, отказ и отмену устаревшего
запроса. Playwright проверяет мобильный браузер в светлой и тёмной теме,
диапазон, участников, неизвестного автора, раскрытие метрик и сравнение месяцев.

Живая семейная таблица и настоящие Android/iOS/Desktop-клиенты Telegram в
автоматических проверках не используются. Их ручная проверка остаётся проверкой
окружения. API при каждом запросе читает всю книгу; большой объём архивов может
потребовать кеширования в будущем.
