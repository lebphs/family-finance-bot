# Безопасная миграция Google Sheets

Этап 3 добавляет отдельную команду миграции. Импорт модулей и запуск приложения
не изменяют схему автоматически. Реальная таблица не используется в тестах.

## Перед началом

1. Остановить бота, API и все другие процессы записи.
2. Создать копию всей таблицы и скачать резервную копию XLSX вне репозитория.
3. На копии проверить листы `Main`, `Preferences`, `Transactions`,
   архивы `Transactions MM.YYYY`; записать число операций и суммы каждого месяца.
4. Подготовить локальную конфигурацию для копии таблицы. Не публиковать ID,
   токен, credentials или данные расходов.

## Команды

Из корня проекта, с установленными зависимостями:

```powershell
python -m mini_app.backend.migration
python -m mini_app.backend.migration --apply
python -m mini_app.backend.migration
```

Первая команда — dry run: никаких записей. Она проверяет обязательные листы,
диапазон категорий, заголовки Users и E–I, дубликаты существующих ID во всех
месячных листах. Отчёт содержит только количества. Конфликт схемы или Google API
завершает команду ошибкой без раскрытия исходного исключения.

Вторую команду запускать сначала на копии, после проверки dry run и резервной
копии. Она создаёт или инициализирует пустой `Users`, расширяет число столбцов
до девяти, заполняет E1:I1 и только отсутствующие G в строках операций.
Заголовки E–I: `telegram_user_id`, `display_name`, `transaction_id`,
`created_at`, `updated_at`. Столбцы A–D, их заголовки, значения, формулы и
форматирование не перезаписываются. Старым операциям не назначаются авторы
или выдуманное время создания.

Повторная команда не меняет существующие ID и не добавляет строки операций.
Запись метаданных выполняется атомарными порциями до 500 диапазонов. После
частичного сбоя повторный запуск продолжает миграцию по незаполненным ячейкам.
Если создание Users успело выполниться, но запись заголовка не удалась, пустой
лист инициализируется при повторе. Непустой Users с неверным заголовком
отклоняется; его данные автоматически не исправляются.

После применения dry run должен показывать ноль отсутствующих ID и
структурных изменений. Сверить число операций, суммы, формулы и форматирование
A–D с резервной копией. Затем повторить процедуру на рабочей таблице.

## Первоначальный доступ

Users создаётся только с заголовками, без автоматически разрешённых участников:

`telegram_user_id, display_name, role, active, reminder_enabled, reminder_time,
reminder_days, timezone, chat_id`.

Доверенный владелец таблицы вручную добавляет первоначального администратора
с проверенным числовым Telegram ID, ролью `admin` и `active=TRUE`. Остальные
пользователи могут быть добавлены через уже реализованный административный API.
До этого приложение и бот отказывают в доступе. Пример настроек напоминания:
`FALSE`, `22:00`, `0,1,2,3,4,5,6`, `Europe/Minsk`, пустой chat_id.
Планировщик персональных напоминаний относится к последующему этапу.

## Работа repositories и ротация

- Все Google Sheets операции HTTP API и бота выполняются в рабочих потоках.
- В одном процессе операции одной таблицы защищены общим lock. Запускать один
  процесс записи; lock не обеспечивает координацию разных серверов или ручных
  изменений в Google Sheets. Для миграции обязательно остановить всех писателей.
- Повторяются только чтения при временных сетевых ошибках, 429 и временных 5xx,
  максимум три попытки. Записи автоматически не повторяются: после таймаута
  проверить результат, прежде чем отправлять расход ещё раз.
- Новые операции получают автора из Users, UUID, created_at и updated_at в UTC.
  Описания сохраняются как текст, даты — как числовые даты Sheets; A–D остаются
  совместимыми с формулами. Изменение и удаление repositories выполняют по ID;
  публичные HTTP endpoints управления транзакциями относятся к будущим этапам.
- Старые операции без автора читаются как «Автор не указан»; до миграции
  операция без ID не может изменяться или удаляться через repository.
- Текущий лист и только архивы вида `Transactions MM.YYYY` читаются совместно.
- Первого числа по Europe/Minsk ротация одним атомарным запросом копирует
  текущий лист в архив предыдущего месяца и очищает A2:I текущего листа.
  ID текущего листа сохраняется, поэтому ссылки Main продолжают указывать на
  Transactions. Заголовок A–I и оформление сохраняются. Уже существующий
  архив делает повторную ротацию пустой операцией.
- Существующая кнопка бота удаления общей последней операции теперь требует
  активного администратора и ID. Настройки и новый интерфейс управления
  транзакциями в этом этапе не реализуются.

## Откат

Если проверка обнаружила изменение A–D, числа операций или конфликт ID,
остановить процессы, восстановить резервную копию и выяснить причину.
Не исправлять рабочие финансовые данные поверх частичной миграции.

## Проверки без внешних сервисов

```powershell
python -m unittest tests.test_sheets_stage3 tests.test_user_repository -v
python -m unittest discover -s tests -v
```

Тесты используют fake worksheets и mock внешних границ. Проверка реальных
формул и оформления на резервной копии остаётся обязательной операционной
приёмкой перед изменением рабочей таблицы.
