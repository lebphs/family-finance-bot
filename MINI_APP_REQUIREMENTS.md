# Family Finance Mini App — требования

Статус: согласованный базовый объём первой версии.

## 1. Назначение

Закрытое Telegram Mini App для ведения общей семейной книги расходов.
Приложение должно позволять быстро добавлять расходы, просматривать и
редактировать транзакции, анализировать расходы семьи и отдельных участников,
а также получать персональные напоминания через Telegram-бота.

Пользовательский интерфейс и сообщения должны быть на русском языке.

## 2. Пользователи и доступ

- Приложение доступно только пользователям из списка разрешённых Telegram ID.
- Данные Telegram Mini App (`initData`) должны проверяться на backend: подпись,
  срок действия и соответствие разрешённому пользователю.
- Нельзя доверять Telegram ID, имени или роли, переданным frontend без проверки.
- В семье используется одна общая книга расходов.
- Все участники видят общие транзакции и статистику семьи.
- Роль `member` может создавать транзакции и изменять или удалять только свои.
- Роль `admin` может изменять и удалять любые транзакции, управлять участниками
  и общими настройками.
- Старые транзакции без известного автора может изменять только администратор.
- Неизвестному или отключённому пользователю показывается экран «Нет доступа»;
  финансовые данные при этом не возвращаются.

## 3. Навигация и интерфейс

Основная навигация:

1. Главная.
2. Транзакции.
3. Статистика.
4. Настройки.

Требования к интерфейсу:

- mobile-first;
- корректная работа в Telegram на Android, iOS и Desktop;
- поддержка светлой и тёмной темы Telegram;
- крупные и удобные элементы управления;
- понятные состояния загрузки, пустых списков и ошибок;
- подтверждение удаления и других опасных действий;
- отсутствие повторной отправки формы при двойном нажатии;
- суммы отображаются в BYN.

## 4. Главная страница

Главная страница предназначена прежде всего для быстрого добавления расхода.

### Форма расхода

- сумма — обязательное положительное число;
- категория — обязательна и выбирается из Google Sheets;
- подкатегория или описание — необязательны;
- дата — текущая по умолчанию, пользователь может её изменить;
- автор определяется сервером по проверенным данным Telegram;
- после сохранения показывается результат операции, а данные на странице
  обновляются.

### Сводка

- общая сумма расходов за текущий месяц;
- изменение относительно предыдущего месяца;
- компактная диаграмма по категориям;
- последние транзакции;
- переход к полному списку транзакций.

## 5. Транзакции

- список сортируется от новых операций к старым;
- фильтры по периоду, категории и участнику;
- поиск по описанию;
- отображение автора операции;
- редактирование даты, суммы, категории, подкатегории или описания;
- удаление только после подтверждения;
- проверка прав на backend перед изменением или удалением;
- каждая операция имеет постоянный уникальный ID и не идентифицируется номером
  строки Google Sheets.

## 6. Статистика

Поддерживаемые периоды:

- текущий месяц;
- последние 2, 3, 6 и 12 месяцев;
- произвольный диапазон месяцев;
- сравнение двух выбранных месяцев.

Показатели:

- общая сумма расходов семьи;
- расходы по категориям;
- динамика общей суммы по месяцам;
- абсолютная и процентная разница между месяцами;
- сумма расходов каждого участника;
- доля участника в общих расходах;
- количество транзакций участника;
- средняя сумма его расхода;
- разбивка расходов участника по категориям;
- сравнение участников;
- динамика расходов каждого участника по месяцам.

Статистику можно смотреть для всей семьи или выбранного участника. Автором
операции считается пользователь, который внёс её в приложение; это не
обязательно человек, на которого фактически были потрачены деньги.

Диаграммы строятся во frontend по числовым данным, полученным от backend.

## 7. Напоминания

Напоминания отправляет существующий Telegram-бот, так как Mini App не работает
самостоятельно в фоне.

Настройки хранятся отдельно для каждого пользователя:

- включены ли напоминания;
- время отправки;
- дни недели;
- часовой пояс;
- Telegram chat ID.

Значение по умолчанию: ежедневно в 22:00, часовой пояс `Europe/Minsk`.
Настройки должны сохраняться после перезапуска приложения. Пользователь должен
иметь возможность включить, отключить и изменить свои напоминания.

## 8. Google Sheets

На первом этапе Google Sheets остаётся основным хранилищем. Существующие листы
`Main`, `Preferences` и `Transactions` сохраняются. Категории и подкатегории
по-прежнему читаются из `Preferences!B4:C43`.

### Структура транзакции

Первые четыре столбца сохраняются для совместимости с текущими формулами:

| Столбец | Значение |
| --- | --- |
| A | Дата |
| B | Описание или подкатегория |
| C | Категория |
| D | Сумма |
| E | Telegram User ID автора |
| F | Отображаемое имя автора |
| G | Уникальный ID транзакции |
| H | Дата и время создания |
| I | Дата и время последнего изменения |

Старые строки без сведений об авторе показываются как «Автор не указан».

Статистика за несколько месяцев рассчитывается по текущему листу
`Transactions` и архивным листам `Transactions MM.YYYY`. Все вновь создаваемые
архивные листы должны сохранять расширенную структуру столбцов.

### Лист Users

Для авторизации и персональных настроек создаётся отдельный лист `Users`:

| Поле | Назначение |
| --- | --- |
| `telegram_user_id` | Числовой Telegram ID |
| `display_name` | Имя в приложении |
| `role` | `admin` или `member` |
| `active` | Разрешён ли доступ |
| `reminder_enabled` | Включено ли напоминание |
| `reminder_time` | Локальное время напоминания |
| `reminder_days` | Дни недели |
| `timezone` | Часовой пояс |
| `chat_id` | Чат для отправки напоминаний |

Telegram username не используется как основной идентификатор, поскольку он
может измениться или отсутствовать.

Все обращения к `gspread` выполняются вне event loop, например через
`asyncio.to_thread`. Ошибки Google API должны обрабатываться без потери введённых
пользователем данных и без раскрытия секретов.

## 9. Архитектура

- frontend: React + TypeScript + Vite;
- backend API: FastAPI;
- Telegram-бот и уведомления: aiogram 3.x;
- источник данных первой версии: Google Sheets;
- frontend обращается к Google Sheets только через backend;
- существующий бот остаётся точкой запуска Mini App и каналом уведомлений.

Предполагаемые группы API:

- авторизация и текущий пользователь;
- категории и подкатегории;
- создание, чтение, изменение и удаление транзакций;
- агрегированная статистика;
- настройки напоминаний;
- управление пользователями для администратора.

## 10. Размещение и секреты

- собственный домен не обязателен;
- рабочее приложение размещается по HTTPS-адресу, предоставленному хостингом;
- для локальной разработки может использоваться временный HTTPS-туннель;
- URL приложения настраивается в BotFather как Main Mini App или кнопка меню;
- `BOT_TOKEN`, `GOOGLE_SHEET_ID` и Google credentials доступны только backend;
- `.env` и `google-credentials.json` не включаются в Docker-образ, frontend,
  логи или систему контроля версий;
- ранее опубликованные секреты считаются скомпрометированными и должны быть
  заменены перед публичным развёртыванием.

## 11. Этапы реализации

### Этап 1. Backend и безопасность

- выделить приложение FastAPI;
- реализовать проверку Telegram `initData`;
- добавить чтение разрешённых пользователей и ролей из `Users`;
- подготовить асинхронную обёртку для Google Sheets;
- добавить конфигурацию и тесты без подключения к реальной таблице.

### Этап 2. Модель данных

- расширить структуру транзакций без изменения столбцов A–D;
- добавить уникальные ID и автора;
- адаптировать ежемесячную ротацию;
- обеспечить чтение текущего и архивных месяцев.

### Этап 3. Главная страница

- форма добавления расхода;
- месячная сводка;
- диаграмма по категориям;
- последние транзакции.

### Этап 4. Управление транзакциями

- список и фильтры;
- редактирование;
- удаление с проверкой прав и подтверждением.

### Этап 5. Статистика

- агрегация по периодам, категориям и участникам;
- сравнение месяцев;
- диаграммы и показатели динамики.

### Этап 6. Напоминания и настройки

- персональное расписание;
- сохранение настроек в `Users`;
- надёжная отправка напоминаний после перезапуска.

### Этап 7. Развёртывание и проверка

- единая версия Python в Docker и окружении;
- `.dockerignore` и безопасная передача секретов;
- HTTPS-развёртывание;
- настройка Mini App в BotFather;
- тестирование основных сценариев на мобильных клиентах Telegram.

## 12. Критерии готовности первой версии

- пользователь вне списка не получает финансовые данные;
- разрешённый пользователь может добавить расход с телефона;
- транзакция сохраняется с постоянным ID и автором;
- участник не может изменить или удалить чужую транзакцию;
- администратор может управлять всеми транзакциями и участниками;
- список транзакций поддерживает согласованные фильтры;
- статистика корректно работает для семьи и отдельных участников за несколько
  месяцев;
- персональные напоминания сохраняются после перезапуска;
- интерфейс работает в светлой и тёмной теме Telegram;
- тесты не обращаются к реальному Telegram или Google Sheets;
- секреты отсутствуют во frontend, образе и репозитории.

## 13. За пределами первой версии

- учёт доходов и переводов между счетами;
- несколько независимых семей в одном экземпляре приложения;
- банковская синхронизация;
- полноценный бухгалтерский учёт;
- переход с Google Sheets на PostgreSQL.
